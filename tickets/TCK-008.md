# [TCK-008] Move Domain Services from `src/lib/` to `src/server/services/` per Blueprint

- **Ticket ID**: TCK-008
- **Related Finding**: [AUD-007](../findings/AUD-007.md)
- **Phase**: Phase D — Architecture & Governance
- **Status**: Draft
- **Assigned Agent**: TBD (Sonnet specialist)

---

## 1. Problem Definition

Domain business logic (`runBostaSync`, `runShopifySync`, `processShopifyWebhookEvent`, `refreshAnalyticsAfterLedgerWrite`), data access repositories (`events-repo.ts`, `running-sync-repo.ts`, `integrations-repo.ts`), and infrastructure adapters (`supabase-adapter`) all reside in `src/lib/` alongside pure utilities. The target-codebase blueprint (§5.1) designates `src/server/services/` for domain logic and `src/lib/` for shared utilities. This violates Ref 09 (Clean Architecture Dependency Rule) and Ref 01 (Ousterhout — module boundaries should hide complexity).

> **Note**: This is a **refactoring-only** move (Ref 06 — Fowler: Move Function). No behavior change. Must be done in a dedicated commit, never mixed with feature work. It depends on TCK-001 (which modifies `integrations-repo.ts`) being completed first to avoid merge conflicts.

---

## 2. Expected Outcome

```
src/server/services/
  sync/
    bosta-sync.ts        ← runBostaSync
    shopify-sync.ts      ← runShopifySync
    analytics.ts         ← refreshAnalyticsAfterLedgerWrite
  webhooks/
    shopify-store-sync.ts ← processShopifyWebhookEvent
```

`src/lib/` retains only: pure utilities (`verify.ts`, `capped-body.ts`, `bosta-key.ts`, `enqueue.ts`) and shared types.

ESLint boundaries config updated to enforce the new layer rules.

---

## 3. Affected Files & Services

- Files moved from `src/lib/sync/`, `src/lib/webhooks/shopify-store-sync.ts`
- All import paths in callers (route handlers, server actions)
- `configs/eslint.config.mjs` — boundary enforcement rules
- Ingestion core (`src/lib/imports/`, `src/lib/shopify/`) — **NOT MOVED** per SeemlyOps hard rules (changes need a test proving behavior unchanged)
