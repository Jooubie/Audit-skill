# [TCK-001] Add RLS Policies to `webhook_events` and `sync_runs` Tables

- **Ticket ID**: TCK-001
- **Related Finding**: [AUD-001](../findings/AUD-001.md)
- **Phase**: Phase A — Security & Data Integrity
- **Status**: Draft
- **Assigned Agent**: TBD (Sonnet specialist)

---

## 1. Problem Definition

The `webhook_events` and `sync_runs` tables have RLS enabled but zero policies defined. All access currently relies on the service-role client (`adminDb()`), which completely bypasses RLS. If any code path ever switches to the user/anon client, full cross-tenant data exposure occurs. This violates Ref 14 (OWASP & Supabase RLS) §3 which mandates "Activate RLS explicitly on all public schema tables during initial migration" and that the service-role key be used only where cross-tenant authority is intentionally required.

---

## 2. Expected Outcome

- Both `webhook_events` and `sync_runs` have RLS policies binding rows to the calling tenant's `tenant_id` via JWT claims.
- Read paths in the integrations screen (`loadIntegrationActivity`) use the user-scoped Supabase client + RLS instead of `adminDb()`.
- Service-role client remains only for webhook receipt writes (which require cross-tenant authority).
- Defense-in-depth: even accidental use of the anon client returns only the caller's own rows.

---

## 3. Affected Files & Services

- New additive migration: `supabase/migrations/YYYYMMDDHHMMSS_rls_webhook_events_sync_runs.sql`
- `src/lib/webhooks/integrations/integrations-repo.ts` (switch `loadIntegrationActivity` from `adminDb()` to user client)
- `src/lib/webhooks/events-repo.ts` (verify service client usage is intentional for writes)

---

## 4. Acceptance Criteria

- [ ] 1. `CREATE POLICY tenant_isolation_webhook_events ON webhook_events FOR ALL USING (tenant_id = (auth.jwt() ->> 'app_metadata' ->> 'tenant_id')::uuid)` applied.
- [ ] 2. Matching policy on `sync_runs`.
- [ ] 3. `FORCE ROW LEVEL SECURITY` set on both tables.
- [ ] 4. `loadIntegrationActivity` uses user-scoped client, not `adminDb()`.
- [ ] 5. Migration file contains `-- REVERSE:` comment block per SeemlyOps rules.
- [ ] 6. `npm run typecheck && npm run lint` pass.
- [ ] 7. No modification of unrelated files.

---

## 5. Regression Test Specification

- **Test type**: pgTAP or SQL-based RLS isolation test
- **Test assertion**: `SELECT * FROM webhook_events` as a non-admin role returns only the calling tenant's rows; a cross-tenant query returns zero rows.
- **Additional**: Existing integration tests continue to pass with the user-client switch.

---

## 6. Risks & Rollback Requirements

- **Risk Assessment**: Medium — switching from `adminDb()` to user client for reads changes the authorization model. Must verify all callers of `loadIntegrationActivity` pass a correctly-scoped client.
- **Rollback Procedure**: `DROP POLICY tenant_isolation_webhook_events ON webhook_events; DROP POLICY tenant_isolation_sync_runs ON sync_runs;` — revert the migration using the REVERSE comment.
