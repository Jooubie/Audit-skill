# [TCK-006] Add Retry with Exponential Backoff for Shopify GraphQL in Webhook Registration

- **Ticket ID**: TCK-006
- **Related Finding**: [AUD-008](../findings/AUD-008.md)
- **Phase**: Phase C — Integration Resilience
- **Status**: Draft
- **Assigned Agent**: TBD (Sonnet specialist)

---

## 1. Problem Definition

`registerMissingWebhooks` calls `shopifyGraphql` for query and mutation operations with no retry, backoff, or rate-limit awareness. During Shopify API degradation (429/503), registration calls fail immediately without retry and consume rate-limit budget. Per Ref 11 (Nygard) — circuit breakers and retry backoff are mandatory for all external service calls. The audit checklist (§4) explicitly requires this.

---

## 2. Expected Outcome

- `shopifyGraphql` calls in `registerMissingWebhooks` are wrapped with retry logic (up to 3 attempts, exponential backoff).
- 429 responses respect `Retry-After` header when present.
- 400-level client errors (except 429) are not retried.
- JSDoc documents rate-limit awareness.

---

## 3. Affected Files & Services

- `src/lib/shopify/client.ts` or `src/lib/webhooks/integrations/shopify-webhooks.ts` — retry wrapper
- Optionally a shared `withRetry` utility if one doesn't exist

---

## 4. Acceptance Criteria

- [ ] 1. 429/503 responses trigger retry with exponential backoff (delay × 2^attempt).
- [ ] 2. Max 3 retry attempts before final failure.
- [ ] 3. `Retry-After` header respected when present.
- [ ] 4. 400 client errors not retried.
- [ ] 5. `npm run typecheck && npm test` pass.

---

## 5. Regression Test Specification

- **Test path**: `tests/webhooks/shopify-webhooks.test.ts` or `tests/shopify/client.test.ts`
- **Expected assertions**:
  - Mock 429 → retries 3 times → returns final result
  - Mock 400 → no retry → returns error immediately
  - Mock success → returns on first attempt

---

## 6. Risks & Rollback Requirements

- **Risk Assessment**: Low — additive retry logic; no behavioral change on success paths.
- **Rollback Procedure**: Git revert; calls return to immediate fail-on-error.
