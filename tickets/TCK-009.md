# [TCK-009] Verify REVERSE Comments on All Migrations + CI Lint

- **Ticket ID**: TCK-009
- **Related Finding**: [AUD-009](../findings/AUD-009.md)
- **Phase**: Phase D — Architecture & Governance
- **Status**: Draft
- **Assigned Agent**: TBD (Sonnet specialist)

---

## 1. Problem Definition

The audit environment cannot verify whether migration `20260917180000` (or any other migration) contains the mandatory `-- REVERSE:` comment block per SeemlyOps schema evolution rules and Ref 02 (Kleppmann). Without documented reverse DDL, rollback during a production incident requires reconstructing the reverse migration under pressure — increasing MTTR.

---

## 2. Expected Outcome

- All migration files in `supabase/migrations/` verified to contain `-- REVERSE:` comments.
- Any missing REVERSE comments are added.
- CI pipeline includes a lint step that fails if any migration file lacks `-- REVERSE:`.

---

## 3. Affected Files & Services

- `supabase/migrations/*.sql` — add missing REVERSE comments
- CI configuration (`.github/workflows/` or `package.json` scripts) — add `grep`-based lint step

---

## 4. Acceptance Criteria

- [ ] 1. All migration files contain `-- REVERSE:` comment blocks.
- [ ] 2. CI step: `grep -rL '-- REVERSE:' supabase/migrations/*.sql` returns empty (exit 0).
- [ ] 3. `configs/squawk.toml` updated if squawk supports custom rules.
- [ ] 4. No modification of migration SQL logic (comments only).

---

## 5. Regression Test Specification

- **Test path**: CI pipeline step
- **Expected assertion**: `grep -rL '-- REVERSE:' supabase/migrations/*.sql` returns exit code 0 (no files without REVERSE)

---

## 6. Risks & Rollback Requirements

- **Risk Assessment**: Low — comment-only changes to migration files; CI lint is additive.
- **Rollback Procedure**: Git revert; remove CI lint step.
