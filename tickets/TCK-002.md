# [TCK-002] Replace Plain-String Equality with `timingSafeEqual` in Bosta Webhook Auth

- **Ticket ID**: TCK-002
- **Related Finding**: [AUD-002](../findings/AUD-002.md)
- **Phase**: Phase A — Security & Data Integrity
- **Status**: Draft
- **Assigned Agent**: TBD (Sonnet specialist)

---

## 1. Problem Definition

`verifyBostaWebhook` authenticates Bosta webhook deliveries by comparing the `x-seemly-webhook-key` header against `BOSTA_WEBHOOK_SECRET` using plain string equality (`===`). This is not timing-safe and is vulnerable to timing-side-channel attacks that can recover the secret byte-by-byte. The Shopify path already uses `timingSafeEqual` correctly. OWASP ASVS Level 2 (Ref 14 §1) mandates timing-safe comparison for all authentication secrets.

---

## 2. Expected Outcome

- `verifyBostaWebhook` uses Node's `timingSafeEqual` via fixed-length SHA-256 hash buffers (preventing length-leak side channel).
- The logical authentication contract (accept if secret matches, reject otherwise) is unchanged.
- `timingSafeEqual` import already exists in the same module for Shopify — no new dependency.

---

## 3. Affected Files & Services

- `src/lib/webhooks/verify.ts` — `verifyBostaWebhook` function

---

## 4. Acceptance Criteria

- [ ] 1. `verifyBostaWebhook` uses `timingSafeEqual` on SHA-256 digests, not `===`.
- [ ] 2. Correct secret → returns `true`; wrong secret → returns `false`; empty secret → returns `false`.
- [ ] 3. No change to Shopify verification logic.
- [ ] 4. `npm run typecheck` passes.
- [ ] 5. Existing `guard-presence.test.ts` passes.

---

## 5. Regression Test Specification

- **Test path**: `tests/webhooks/verify.test.ts` (new or extended)
- **Expected assertions**:
  - `verifyBostaWebhook(headersWithCorrectKey, secret)` → `true`
  - `verifyBostaWebhook(headersWithWrongKey, secret)` → `false`
  - `verifyBostaWebhook(headersWithEmptyKey, secret)` → `false`
  - `verifyBostaWebhook(headers, '')` → `false`
- Code review confirms `timingSafeEqual` is used (not `===` or `.equals()`)

---

- **Risk Assessment**: Low — minimal change; same function signature; no behavioral change to callers.
