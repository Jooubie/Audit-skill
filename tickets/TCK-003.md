# [TCK-003] Surface `markWebhookEvents` Failures as Structured Error Results

- **Ticket ID**: TCK-003
- **Related Finding**: [AUD-003](../findings/AUD-003.md)
- **Phase**: Phase B — Reliability & Fail-Fast
- **Status**: Draft
- **Assigned Agent**: TBD (Sonnet specialist)

---

## 1. Problem Definition

`markWebhookEvents` silently swallows DB update failures with only `console.error`. Since this runs in `after()` context (post-response), failures cannot propagate to the client. The result is phantom `received` events that the sweeper later marks as `error`, polluting the integration health dashboard and masking real delivery failures. Per Ref 11 (Nygard) — steady state requires surfacing operational debt, not accumulating it silently.

---

## 2. Expected Outcome

- `markWebhookEvents` returns a structured result type `{ updated: number; error: Error | null }` instead of swallowing errors.
- Callers can inspect the result and emit structured logs or metrics for alerting pipelines.
- The integration health dashboard (`syncRunsRecorded`) is not affected by the return type change.
- No behavior change for the `after()` context — the function still does not throw.

---

## 3. Affected Files & Services

- `src/lib/webhooks/events-repo.ts` — `markWebhookEvents` function signature and error handling
- All callers of `markWebhookEvents` (in `after()` blocks of webhook route handlers)

---

## 4. Acceptance Criteria

- [ ] 1. `markWebhookEvents` returns `{ updated: number; error: Error | null }`.
- [ ] 2. On DB error, `error` field is populated with context (event IDs, status attempted).
- [ ] 3. Callers updated to handle the new return type (at minimum, structured logging).
- [ ] 4. No `throw` in `after()` context — function still never throws.
- [ ] 5. `npm test` passes; existing `events-repo.ts` tests updated for error path.

---

## 5. Regression Test Specification

- **Test path**: `tests/webhooks/events-repo.test.ts`
- **Expected assertions**:
  - When DB returns success: `{ updated: N, error: null }`
  - When DB returns error: `{ updated: 0, error: <Error> }` with structured context
  - Integration health reads unaffected

---

## 6. Risks & Rollback Requirements

- **Risk Assessment**: Low — return type addition is backwards-compatible; callers that don't inspect the result continue to work.
- **Rollback Procedure**: Git revert the commit.
