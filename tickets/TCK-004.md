# [TCK-004] Return 503 on Enqueue RPC Failure Instead of Silent 200

- **Ticket ID**: TCK-004
- **Related Finding**: [AUD-006](../findings/AUD-006.md)
- **Phase**: Phase B — Reliability & Fail-Fast
- **Status**: Draft
- **Assigned Agent**: TBD (Sonnet specialist)

---

## 1. Problem Definition

When `JOB_QUEUE=on`, webhook routes call `rpc_enqueue_job` to queue sync work. If the RPC fails, the route silently answers 200. Bosta and Shopify believe delivery is acknowledged and do not retry. The event stays in `received` status until the stuck-event sweeper runs (up to 30+ minutes later), creating an unbounded data-gap window. Per Ref 11 (Nygard) — this violates fail-fast mechanics and delegates all recovery to a periodic sweeper.

> **Decision Required**: The original 200-on-failure was a deliberate design choice to avoid Shopify retry floods when the queue is backed up. Changing to 503 trades retry safety for flood risk. **This ticket requires Jou's explicit decision** on the trade-off.

---

## 2. Expected Outcome

- When `enqueueWebhookJob` fails, webhook routes return `503 Service Unavailable` instead of 200.
- Both Bosta and Shopify retry on 5xx responses with their built-in backoff mechanisms.
- The `webhook_events` row remains in `received` status (unchanged), but the provider's retry delivers the event again, triggering a fresh enqueue attempt.
- Structured log line emitted on enqueue failure for alerting.

---

## 3. Affected Files & Services

- `src/lib/webhooks/enqueue.ts` — change `enqueueWebhookJob` to return a result instead of swallowing errors
- `src/app/api/webhooks/bosta/route.ts` — check enqueue result, return 503 on failure
- `src/app/api/webhooks/shopify/[store]/route.ts` — same

---

## 4. Acceptance Criteria

- [ ] 1. `enqueueWebhookJob` returns `{ ok: boolean; error?: Error }` instead of never-throws.
- [ ] 2. Bosta route handler returns `503` when `enqueueResult.ok === false`.
- [ ] 3. Shopify route handler returns `503` when `enqueueResult.ok === false`.
- [ ] 4. Structured error log emitted with source and event context.
- [ ] 5. Bosta/Shopify retry behavior verified against their webhook retry documentation.
- [ ] 6. `npm test` passes; existing guard-presence tests pass.

## 5. Regression Test Specification

- **Test path**: `tests/webhooks/enqueue.test.ts`, `tests/api/webhooks/bosta.test.ts`, `tests/api/webhooks/shopify.test.ts`
- **Expected assertions**:
  - When `rpc_enqueue_job` succeeds: route returns 200
  - When `rpc_enqueue_job` fails: route returns 503; `webhook_events` row is in `received`

---

## 6. Risks & Rollback Requirements

- **Risk Assessment**: Medium — returning 503 triggers Shopify/Bosta retries. Under sustained DB failure, retries could create load spikes. Mitigated by provider-side exponential backoff.
- **Rollback Procedure**: Git revert; routes return 200 on failure again.
- **Requires**: Jou's decision on the 200-vs-503 trade-off before implementation.
