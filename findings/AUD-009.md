# [AUD-009] Governance: No Additive Migration Reverse Comment Verifiable from Audit Scope

- **Finding ID**: AUD-009
- **Severity**: Informational
- **Confidence**: Medium
- **Category**: Governance
- **Location**: Migration `20260917180000` (cited in `src/lib/webhooks/events-repo.ts`)

---

## 1. Description & Evidence

The `events-repo.ts` README comment references migration `20260917180000` as the one creating the unique `(source, delivery_key)` constraint on `webhook_events`. SeemlyOps hard rules (from AGENTS.md) mandate:

> "Schema changes are new additive migrations with a REVERSE comment; never edit an applied one."

The audit environment does not have access to the migrations directory to verify the REVERSE comment is present on migration `20260917180000` or any other. This is a governance gap — the audit cannot confirm compliance with the schema evolution policy (Ref 02, Kleppmann) from available files.

**Canon Reference**: Ref 02 (Kleppmann Schema Evolution) §3 — Zero-downtime DDL requires documented safe-down steps. The SeemlyOps engineering contract mandates REVERSE comments on every migration.

---

## 2. Actual or Credible Failure Scenario

If migration `20260917180000` lacks a REVERSE comment and a rollback is needed (e.g., the unique constraint is too restrictive), the engineer must reconstruct the reverse DDL from the forward migration — increasing rollback risk during a production incident.

---

## 3. Technical & Business Impact

- **Technical Impact**: Slower, error-prone rollbacks without documented reverse DDL; risk of incorrect constraint removal during incident response.
- **Business Impact**: Extended MTTR during migration-related incidents.

---

## 4. Proposed Correction

1. Access the full migrations directory and verify every migration file contains a `-- REVERSE:` comment block.
2. For `20260917180000`, the reverse would be:
   ```sql
   -- REVERSE: DROP INDEX IF EXISTS idx_webhook_events_source_delivery_key;
   -- REVERSE: ALTER TABLE webhook_events DROP CONSTRAINT IF EXISTS webhook_events_source_delivery_key_key;
   ```
3. Add a CI lint step (`squawk` or a custom grep) that fails if any migration file lacks a `-- REVERSE:` comment.

---

## 5. Verification Criteria

- [ ] All migration files in the migrations directory contain `-- REVERSE:` comments
- [ ] CI pipeline runs `grep -L '-- REVERSE:' supabase/migrations/*.sql` and fails on any match
- [ ] `configs/squawk.toml` updated to include the check if squawk supports custom rules
