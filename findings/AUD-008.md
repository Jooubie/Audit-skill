# [AUD-008] No Circuit Breaker or Backoff for Shopify GraphQL Calls in Webhook Registration

- **Finding ID**: AUD-008
- **Severity**: Low
- **Confidence**: Medium
- **Category**: Reliability
- **Location**: `src/lib/webhooks/integrations/shopify-webhooks.ts` — `registerMissingWebhooks`, `listWebhookSubscriptions`

---

## 1. Description & Evidence

The README confirms `registerMissingWebhooks` calls `shopifyGraphql` for a query (`webhookSubscriptions`) and potentially multiple mutations (`webhookSubscriptionCreate` per missing topic). There is no mention of:

- Retry with exponential backoff for transient Shopify API errors
- Circuit breaker to stop hammering Shopify under sustained failure
- Rate-limit header inspection (`X-Shopify-Shop-Api-Call-Limit`)

**Canon Reference**: Ref 11 (Nygard Production Stability) — "Circuit breakers: automatically stop calls to a failing remote service before resource exhaustion." Ref 11 also mandates timeouts for all external calls.

The audit checklist (§4) explicitly requires: "Rate limiting, retry backoff, and circuit breaking for third-party integrations."

---

## 2. Actual or Credible Failure Scenario

During a Shopify API degradation (429 or 503 responses), the integrations screen's webhook registration call fails immediately. If an operator triggers re-registration repeatedly during the outage, repeated failed GraphQL mutations pile up, consuming Shopify API rate-limit budget even during failure, potentially hitting the call limit for the store's normal sync operations.

---

## 3. Technical & Business Impact

- **Technical Impact**: API rate-limit exhaustion; webhook registration failures not retried with backoff; sync operations impacted by registration calls consuming quota.
- **Business Impact**: New store onboarding may fail silently during Shopify API incidents; Shopify sync may degrade if rate limit is consumed by failed registration retries.

---

## 4. Proposed Correction

Wrap `shopifyGraphql` calls in `registerMissingWebhooks` with:
1. **Retry with exponential backoff** (up to 3 attempts, doubling delay) for 429/503 responses
2. **Respect `Retry-After` header** when present
3. Document rate-limit awareness in the function's JSDoc

This can be implemented as a thin wrapper in `src/lib/shopify/client.ts` that all callers benefit from.

---

## 5. Verification Criteria

- [ ] Unit test: `registerMissingWebhooks` retries on 429 up to 3 times with backoff
- [ ] Unit test: does not retry on 400 (client error — no retry benefit)
- [ ] `npm test` passes
